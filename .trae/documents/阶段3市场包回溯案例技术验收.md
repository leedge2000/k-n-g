# 阶段 3：市场包回溯案例技术验收

## 1. 摘要与目标

阶段 3 的市场包代码、`市场工作台` 页面与 G3-1—G3-7 单元/集成门已存在并通过全量回归。缺口是同一份口径清单要求的**回溯案例**从未被端到端证明，且现有 `asOf` 查询存在前视。

本阶段目标：

1. 让 `asOf` 查询真正按「当时可知」回放：序列点位、事件、断言、概览计数不再返回未来信息。
2. 固定 6 个时间截面的回溯情形，期望值逐项可追溯到 `seed_market` 常量与口径清单。
3. 新增只读快照评测器与机器可读报告，输出指标与技术硬门。
4. 保持既有 API 字段与默认行为兼容。

本阶段只处理技术验收，不改变业务口径、不引入真实行情、不触碰正式库。

## 2. 当前状态与问题边界

- `tests/test_market.py`：G3-1—G3-7 覆盖种子幂等、单位口径、序列 as-of 分组、影响触发、断言去重、传导正反查。

- `ontology_ly/packs/market/stage3_市场包口径清单.md`、`stage4_联动与扩面口径清单.md`：停滞口径、单位与状态定义。

### 2.2 必须先以回归证实并修复的前视问题

| 位置 | 现状 | 风险 |
| --- | --- | --- |
| `series_detail()` | `asOf` 只传给 `impacts`，`points`/`events` 全量返回 | 回溯会看到未来价格与未来事件 |
| `overview()` | `asOf` 仅回显，五项计数为全量 | 概览在历史截面失真 |
| `timeline()` | 计算 `state`，但不排除 `announceTime` 晚于 `asOf` 的事件 | 未来才公告的事件提前出现 |
| `assertions()` | 无 `asOf` 参数 | 会读到事后观点 |

字段事实：

- `PriceDataPoint.publishedAt` = 当月 1 日 + 35 天，`T00:00:00Z`。
- `Event.announceTime` 为公告时刻，`effectiveFrom/effectiveTo` 为生效区间。
- `Assertion.assertedAt` 为观点日期。
- 事件状态：`PENDING / ANNOUNCED / EFFECTIVE / EXPIRED`。

## 3. 回放语义（本阶段唯一口径变更）

- **可知性**：信息在 `as-of` 当日结束前已发布即可见。
  - 点位：`publishedAt` 的日期部分 `<= asOf`。
  - 事件：`announceTime` 的日期部分 `<= asOf`。
  - 断言：`assertedAt <= asOf`。
- **状态**：沿用 `event_state()` 在 `asOf` 求值。
- **影响触发**：沿用 `impact_triggered()`，以事件 `effectiveFrom` 为基准加 `lagDays`。
- **默认值**：不传 `asOf` 时取今天。今日所有种子信息均已发布，因此默认结果与当前行为一致。
- **字段兼容**：既有字段不改名、不删减；仅在 `series_detail` 增加 `asOf`，并为其中的 `events` 补齐 `state/stateLabel/triggeredImpactCount`（与 `timeline` 对齐）。

## 4. 固定回溯情形（technical-smoke）

以 `seed_market()` 为唯一事实源，六个截面：

| 情形 | 截面 | 关键预期 |
| --- | --- | --- |
| S3-BT-01 | 2024-02-01 | 无任何点位（首期发布日为 2024-02-05）、无事件 |
| S3-BT-02 | 2024-03-15 | 每序列 2 个点位；EV-1001 `EFFECTIVE` 且触发 1 条影响，EV-1005 `ANNOUNCED` |
| S3-BT-03 | 2024-06-20 | 每序列 5 个点位；EV-1001/1004/1005 `EFFECTIVE` 各触发 1 条影响，EV-1002 `ANNOUNCED` |
| S3-BT-04 | 2024-08-15 | 每序列 7 个点位；EV-1001 `EXPIRED`，EV-1002/1003/1004/1005/1006 `EFFECTIVE`；EV-1004/1005 触发影响 |
| S3-BT-05 | 2024-10-15 | 每序列 9 个点位；EV-1001/1003/1004 `EXPIRED`，EV-1002/1005/1006 `EFFECTIVE`；仅 EV-1005 触发影响；断言 6 组 |
| S3-BT-06 | 2025-01-15 | 每序列 12 个点位（全量 96）；EV-1002 `EFFECTIVE`，其余 `EXPIRED`；断言 6 组 |

每个情形同时校验：

1. 概览五项计数与 `latestPeriod`。
2. 指定序列的点位数量、最后可见 `periodId`、单位与计价口径。
3. 可见事件集合与逐事件 `state`。
4. `timeline` 的 `triggeredImpactCount`。
5. 断言分组数（`AST-0003`/`AST-0004` 同主体同目标同谓词合并后为 1 组；证据 ID 细节仍由 `tests/test_market.py` 覆盖）。
6. 传导图 6 节点、4 条边（`elasticity/lagDays/samplePeriodId` 字段级细节由 G3-7 回归覆盖）。
7. 前视检查：任何 `publishedAt > asOf` 的点位或 `announceTime > asOf` 的事件即为失败。

## 5. 评测器与硬门

新增 `ontology_ly/tools/evaluate_stage3.py`，接口与阶段 1/2 保持一致：

```python
def summarize_cases(cases: list[dict[str, Any]]) -> dict[str, Any]
def build_hard_gates(metrics: dict[str, Any], deterministic: bool,
                     isolation_passed: bool, read_only_passed: bool,
                     source_hashes_valid: bool) -> dict[str, Any]
def run_evaluation(cases_path=..., database_path=..., workspace=None) -> dict[str, Any]
```

执行方式：

- 每个情形从正式 `data/grain_oil.db` 复制独立 `snapshot.db`，只读调用公开 API。
- 不调用任何写接口；`/api/market/*` 全部为 GET。
- 冷/热各调用一次并比较完整响应。
- 记录正式库、情形文件、口径清单的前后 SHA-256。

指标：

- 情形通过率、状态一致率、影响触发一致率、概览计数一致率、断言分组一致率、传导与口径完整率。
- 前视泄漏数（必须为 0）。
- 空分母一律返回 `None`，不得写死为 0。

硬门：

`deterministicOutput`、`formalDataUnchanged`、`readOnlyAccess`、`sourceHashesValid`、`noLookahead`、`casePassRate`、`eventStateAgreement`、`impactAgreement`、`overviewAgreement`、`assertionGroupAgreement`、`transmissionIntegrity`、`overall`。

报告标注：

```json
{"datasetTier": "technical-smoke",
 "businessQualityGate": "NOT_ASSESSED",
 "productionPerformanceGate": "NOT_ASSESSED"}
```
