# 阶段 4 + 5 联动与运营技术验收

## 1. 目标与边界

按阶段 3 已固化的验收规格，为阶段 4（联动与扩面）与阶段 5（运营）补齐**隔离评测器、固定情形夹具、机器可读报告**，使两个阶段从「有代码 + 有回归测试」升级为「有可复现、可审计的技术验收证据」。

本计划只做验收证据与必要的最小修复，不新增业务功能、不改既有 API 契约、不改种子口径。

**证据等级（必须如实标注）**：

- `datasetTier = "technical-smoke"`：情形期望值来自合成种子与冻结口径清单，不代表真实行情或业务金标。
- `businessQualityGate = "NOT_ASSESSED"`：不做业务专家评审。
- `productionPerformanceGate = "NOT_ASSESSED"`：不做生产环境性能/并发验收。

## 4. 夹具设计

两个夹具共用顶层结构（与 `stage3_backtest_smoke.json` 对齐）：

```json
{
  "schemaVersion": "1.0.0",
  "stage": "Stage 4",
  "datasetTier": "technical-smoke",
  "description": "...",
  "source": {"files": [{"path": "...", "sha256": "..."}]},
  "cases": []
}
```

每个 case 含 `caseId / title / kind / expected`。`kind` 决定评测动作：

- `api`：只读 GET 路由结构与取值断言。
- `gate-negative`：在独立副本库注入破坏后调用 `validate_stage4/5()`，断言错误含门编号与对象 ID。
- `service`：直接调用服务方法（事件状态、影响触发、演进状态机、告警生命周期）。

## 5. 评测器设计

### 5.1 隔离与确定性

- 每个 case 使用 `TemporaryDirectory` 下的**独立数据库副本**（`shutil.copy2` 正式库），`Settings(auto_seed=True, scheduler_enabled=False, graph_backend="relational")`。
- 禁止写入正式库；评测开始与结束各记一次 `data/grain_oil.db` 的 SHA-256，必须一致。
- 每个 case 冷/热两次执行（同一副本库上重复调用只读接口或重建副本），响应 JSON 规范化后哈希必须一致。
- 任一 case 抛错只记录该 case 失败，不中断整轮；最终由硬门汇总判定。

### 5.2 指标（空分母返回 `null`，不得报 0 或 1）

阶段 4：`casePassRate`、`eventStateAgreement`、`impactAgreement`、`scopeAgreement`、`routeShapeAgreement`、`bridgeIntegrity`、`gateNegativeDetectionRate`、`deepLinkAgreement`、`noWriteRoutes`。

阶段 5：`casePassRate`、`metricAgreement`、`alertLifecycleAgreement`、`ingestAgreement`、`evolutionAgreement`、`rollbackRestoreIntegrity`、`gateNegativeDetectionRate`、`permissionAgreement`、`knowledgeTablesUnchanged`。

### 5.3 硬门（全 True 才 `overall.passed=true`）

两个评测器共用的硬门：

- `deterministicOutput`：冷/热两轮摘要哈希一致。
- `formalDataUnchanged`：正式库 SHA-256 前后一致。
- `sourceHashesValid`：夹具声明的口径清单与种子文件 SHA-256 与磁盘一致。
- `isolatedDataset`：所有 case 均在临时副本库执行，正式库零写入。
- 各业务指标 = 1.0（或阶段 5 的 `knowledgeTablesUnchanged = true`）。
- 阶段 4 追加 `noWriteRoutes = true`；阶段 5 追加 `permissionAgreement = 1.0`。

## 6. TDD 实施步骤

1. **RED**：新增 `tests/test_stage4_evaluator.py`、`tests/test_stage5_evaluator.py`，覆盖：
   - 夹具 schema 与 caseId 唯一性；

   - 报告元数据必须含三项证据等级标注；
   - `formalDataUnchanged` 在哈希不一致时失败。
   先运行并记录失败。

## 8. 风险与处理

| 风险 | 处理 |
|---|---|
| 正式库被 uvicorn 占用导致哈希读取失败 | 用 Python 以只读字节流计算 SHA-256，不用 PowerShell `Get-FileHash` |
| 阶段 5 的 POST 操作污染正式库 | 全部 case 在临时副本库执行；正式库只读哈希 |
| 时间相关指标（近 7 天、巡检时刻）导致结果不稳定 | 评测注入固定 `now` 或只断言口径与结构，不断言绝对时间值 |
| 阶段 4/5 评测器重复代码 | 允许少量重复，优先保证各自可独立运行；不做跨阶段抽象 |
| 现有回归断言与运行环境耦合 | 出现失败先判断是否环境问题，不为了绿灯弱化断言 |
