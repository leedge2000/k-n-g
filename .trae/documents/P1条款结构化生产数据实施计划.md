# P1 条款结构化生产数据实施计划

> 状态：本轮已于 2026-11-15 完成，下文保留当时口径（DRAFT、RuleTestCase=0）。后续 P1 → P2 正式化（CONFIRMED、9 条测试用例、nemo 引擎）记录在《公开数据版需求整理-政策影响链与业务预警.md》5.8 与 6.4。

## Context

生产库已有 POL0001 的 3 条最低收购价条款，但 `NormativeStatement`、`CompiledRule`、`RuleTestCase` 均为 0，导致 P2 只能使用 fallback-v1。现有 2b/2c 服务已完整实现冻结口径，本轮不重复开发规则引擎，而是用既有能力生成真实、可回链的 P1 数据。

本轮范围仅为一级政策注册表已登记的 POL0001。自动产物全部保持 DRAFT，不把技术验证冒充专家确认，不自动启用正式 Nemo 推理，也不扩展到其余 11 条尚未完成条款拆分与一级政策资格登记的政策。

## 实施步骤

1. **执行前检查与备份**
   - 只读确认 Policy=12、Policy_Clause=3，且目标派生表仍为空。
   - 使用 SQLite 在线备份 API 创建带 UTC 时间戳的 `grain_oil.db.before_p1_*` 备份，校验备份可打开、`integrity_check=ok`，记录源库与备份 SHA-256。

2. **在临时副本演练**
   - 复制到工作区外的临时库，调用现有 `Pack2bService.extract("POL0001")` 与 `Pack2cService.compile("POL0001")`，不手写业务 SQL、不新增填充脚本。
   - 连续执行两轮，核对结果与稳定 ID 不变；演练结束后删除临时库。

3. **生产库生成 P1 资产**
   - 显式针对 POL0001 各执行一次 2b 抽取和 2c 编译。
   - 预期生成：3 条 `NormativeStatement`、3 条主 `ClauseCondition`、3 条 `RuleParameter`、3 条 `CompiledRule`；三条陈述均为 DEFINITION，vaguenessFlag=0。
   - 不创建 `RuleTestCase`，避免未评审技术用例触发后续重抽/重编译保护；不生成例外、后果或条款关系。

4. **验证数据与审计边界**
   - 校验每条 statement 的 charStart/charEnd 可逐字回切父条款，rule→statement→clause→POL0001 回链完整，参数和条件无孤儿、无重复。
   - statement/rule 均为 DRAFT；confirmedBy/confirmedAt 留空；backTranslationMatch=NULL；testcaseIds=[]；RuleTestCase=0。
   - 运行 `PRAGMA foreign_key_check` 与 `PRAGMA integrity_check`，并确认 Policy、Policy_Clause 原始内容未被改写。
   - 验证常规判定仍为 fallback-v1；不将 DRAFT 规则描述为已具备正式推理资格。

5. **回归与文档同步**
   - 先跑 2b、2c、结论层和规则运行时专项测试，再跑全量 `pytest -q`。
   - 更新《公开数据版需求整理-政策影响链与业务预警.md》第 4、5 层实测现状：POL0001 已有 3 条 DRAFT 陈述和 3 条 DRAFT 编译规则；正式 Nemo 仍待专家确认、回译一致及有效测试用例。
