# 真实数据接入实施计划（五域网页抓取 + 系统级爬虫）

## 1. 目标与边界

把当前全部来自 `seed/` 合成种子的演示数据，替换为从公开网站抓取的真实数据，覆盖五个知识域：政策法规、市场价格与指标、年鉴记录、农业情报、知识关系。**爬虫作为系统功能**，集成到现有 `Crawler` + `CrsSource` 机制中（而非一次性脚本），可通过 `POST /api/crawl/trigger` 单源触发或 `POST /api/crawl/run-all` 全量导入，并可由 `CrawlScheduler` 后续定时调度。

**硬性约束（来自既有经验）**：
- 不编造数据。某个源抓取失败就如实标 `notFetched`，不用合成数据回填。
- 不破坏现有 API 契约；新增 `extractorType` 列是可空追加列，老行保持 NULL = 纯文本采集（现有行为）。
- 全部只读访问源站；导入前用 SHA-256 记录正式库基线，导入后比对只增不减。
- 报告标注 `datasetTier = "real-sourced"`，来源与抓取时间可追溯。

## 2. 架构：爬虫成为系统功能

### 2.1 CrsSource 增加 `extractorType` 列

在 `seed/mapping.json` 的 `CrsSource` 表增加可空列 `extractorType TEXT`。`Database._backfill_columns()` 会在 `initialize()` 时自动 `ALTER TABLE` 补齐，不影响已有行。

`extractorType` 取值与抽取器映射：

| extractorType | 抽取器 | 产出表 |
|---|---|---|
| `policy_gov` | `PolicyExtractor` | Policy + SourceDoc(详情页) |
| `market_index_moa` | `MarketIndexExtractor` | Indicator + IvdData |
| `yearbook_stats` | `YearbookExtractor` | YrbYearbook |
| `intel_agri` | `IntelExtractor` | Intel + SourceDoc |
| `relation_derive` | `RelationDeriver` | Relation |
| NULL/空 | — | 仅 SourceDoc（现有行为） |

### 2.2 抽取器框架（`app/extractors.py`）

```python
class BaseExtractor:
    extractor_type: str = ""
    def extract(self, source, html, doc_id, actor, fetch) -> ExtractionResult: ...
```

- `source`：CrsSource 行
- `html`：`sourceUrl` 抓到的页面 HTML
- `doc_id`：列表页已存的 SourceDoc.docId
- `actor`：操作人
- `fetch(url)`：复用 `Crawler.fetch`，供列表页→详情页二次抓取
- 返回 `ExtractionResult(records=[(table, values)], sub_documents=[SourceDoc_payload])`

### 2.3 Crawler 调度（`app/crawler.py`）

`_execute()` 在存入列表页 SourceDoc 后，若 `source["extractorType"]` 非空：
1. 从 `EXTRACTORS` 注册表取对应抽取器
2. 调用 `extract()` 得到 `records` + `sub_documents`
3. 每个 `sub_document` 经 `knowledge.register_source()` 存为 SourceDoc+段
4. 每条 `record` 经 `db.insert(table, values, conn, actor, upsert=True)` 写入，并 `db.log_change(...)`
5. run 结果增加 `extractedCount`、`structuredTables`

### 2.4 系统级入口

- `POST /api/crawl/trigger`（已有）：单源触发，自动跑抽取
- `POST /api/crawl/run-all`（新增）：按知识域顺序触发所有 enabled 源，返回每域计数
- `CrawlScheduler`（已有）：后续可配 cronExpr 定时调度，无需改动

## 4. 各域字段映射

### 政策法规（Policy）
- 列表页 `gov.cn/zhengce/zuixin/` 取前 N 条，过滤标题含「粮食/粮油/大豆/玉米/小麦/稻谷/食用油/农业/收购/补贴」
- 详情页抽取：`policyTitle`、`docNumber`（发文字号）、`issuer`（发布机构）、`effectiveDate`（发布日期）、`summary`（正文前 500 字）
- `regionId`=REG0001（中国）、`knowledgeCategoryId`=KTC0146（政策法规）、`reviewStatus`=已发布
- `sourceDocId` 指向详情页 SourceDoc

### 市场价格与指标（Indicator + IvdData）
- `data.moa.gov.cn/nyb/pc/200zs.jsp` 抽取：粮油产品批发价格指数、粮食价格指数、食用油价格指数、日期、日涨跌
- `Indicator`：`indicatorCode` 如 `MKT-GRAIN-OIL-INDEX`，`sourceOrg`=农业农村部，`unit`=指数
- `IvdData`：`value`=指数值，`period`=日期，`regionId`=REG0001，`commodityId` 对应粮油/粮食/食用油品种，`status`=已发布

### 年鉴记录（YrbYearbook）
- 入口：`stats.gov.cn/sj/ndsj/2025/left.htm`（GB18030），目录页解析出表号 → 表名 → 图片地址
- 统计表为 JPG 图片（如 `html/C12-10.jpg`），由 `app/yearbook.py` 完成：裁剪放大分块 → Windows 内置 OCR（zh-Hans-CN）→ 等距网格还原行列（年份列 k=-1，数据列 x=136+85.35k）→ 跨年一致性校验
- 抽取：`statYear`、`tableName`、`indicatorId`、`regionId`、`commodityId`、`value`、`unit`，`caliberNote` 标注「12-10 表图像识别（图片 sha）」
- OCR 结果缓存于 `data/yearbook_parsed/<sha256>.json`；已导入 1978–2023 共 24 年 117 条
- 缺口如实保留：2014/2024 整行年份识别失败未导入，2005/2011 稻谷、2015 玉米单元格未识别，均不推断补值

### 农业情报（Intel）
- 抓取 moa.gov.cn 或 gov.cn 粮油市场分析/国际粮情栏目
- `intelTitle`、`intelType`、`publishOrg`、`publishDate`、`keyPoints`、`regionId`、`commodityId`、`status`=已发布

### 知识关系（Relation）
- 由已入库 Policy/IvdData/YrbYearbook/Intel 的 `commodityId` + `regionId` 派生「品种—地区」关系
- `subjectEntityType=品种`、`predicate=主产于`、`objectEntityType=地区`、`confidence=1.0`

## 5. 导入顺序与验证

1. 备份 `data/grain_oil.db` → SHA-256 记录基线
2. 注册 5 条真实 CrsSource（各域一条，`enabledFlag=启用`）
3. `run-all` 逐域触发：政策 → 指标 → 年鉴 → 情报 → 关系
4. 触发 `OntologyService.sync()`、`ScopeService.initialize()`、`MarketService.initialize()`
5. 重跑 `validate_stage0.py`、`evaluate_stage3/4/5.py`（标注 `datasetTier=real-sourced`）
6. 生成 `ontology_ly/tools/realdata_import_report.json`
